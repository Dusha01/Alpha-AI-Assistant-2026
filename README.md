# Alpha-AI-Assistant-2026

ИИ-помощник «Альфа-Курса» в Telegram. Отвечает по материалам платформы, подбирает курсы и шаблоны, помнит сферу и режим налога, ставит напоминания. Поиск идёт по векторам в PostgreSQL (pgvector), формулировку ответа пишет LLM с API, совместимым с OpenAI.

Все команды ниже вводятся из **корня репозитория**: папка, где лежат этот `README.md`, `.env.dev.example` и каталог `scripts`.

Дальше сначала запуск, затем как устроен бот.

---

## Запуск

Есть два рабочих способа. Оба читают один и тот же `.env.dev` и один и тот же дамп базы.

| Способ | Что поднимается | Когда выбирать |
|--------|-----------------|----------------|
| [База в Docker, бот из venv](#база-в-docker-бот-из-venv) | Postgres в контейнере, бот — `uvicorn` на компьютере | Обычная разработка: правки в `src/` подхватываются `--reload` |
| [Весь стек скриптом](#весь-стек-скриптом) | `./scripts/dev/up-dev.sh`: Postgres, миграции, загрузка знаний, контейнер бота | Проверка, что Docker-сборка и healthcheck живые |

Факты («Кстати…») сами не появляются после загрузки знаний. Их отдельный шаг описан в [Заполнение фактов](#заполнение-фактов).

### Что установить заранее
1. **Docker** с Compose V2. Проверка: `docker compose version` печатает версию.
2. **Python 3.12** — для бота из venv и для тестов. Проверка: `python3.12 --version`.
3. **Дамп каталога** — один файл `pg_restore`, не папка:
   `src/data/backups/alfa_course_hackathon.backup`.
   В git его нет, его выдаёт команда или он лежит в материалах хакатона.
4. **Токен Telegram-бота** от [@BotFather](https://t.me/BotFather).
5. **Доступ к LLM**: адрес API, ключ и имя модели. Бот читает их из `.env.dev`.

 Нужен доступ в интернет при первом запуске: Docker скачает образы, pip скачает библиотеки, загрузка знаний скачает модель эмбеддингов `intfloat/multilingual-e5-small` (сотни мегабайт).

### Секреты: файл `.env.dev`

Рабочий файл — `.env.dev` в корне. В git он не попадает. Образец без ключей — `.env.dev.example`.

```bash
cp .env.dev.example .env.dev
```

Каждая настройка — строка `ИМЯ=значение`. Значение сразу после `=`, без кавычек и без пробелов вокруг `=`. Пустое значение после `=` значит «не задано».

Обязательно заполнить своими данными:

| Строка | Откуда | Замечание |
|--------|--------|-----------|
| `TELEGRAM_BOT_TOKEN` | BotFather | Целиком, вида `7123456789:AAH...` |
| `LLM_BASE_URL` | Адрес API | **Без** хвоста `/v1`. Программа сама дописывает `/v1/chat/completions` |
| `LLM_API_KEY` | Ключ того же провайдера | Как выдали |
| `LLM_MODEL` | Имя модели | Точное имя у этого провайдера |

`LLM_FALLBACK_MODEL` можно оставить пустым. Если указать второе имя, бот попробует его, когда первая модель не ответит.

`APP_ENV` оставьте `dev`. От него зависит, какой файл настроек читается: `dev` и всё, кроме `prod`, — `.env.dev`; строго `prod` — `.env.prod`. Файл выбирается в момент импорта настроек, по переменной окружения процесса, а не по строке внутри файла.

#### Прокси Telegram

`TELEGRAM_PROXY_URL` оставьте пустым, если Telegram доступен напрямую. В логе будет «Telegram API: прямое подключение». Прокси используется **только** для сессии Telegram, не для LLM и не для скачивания модели.

Подходят схемы `http`, `https`, `socks4`, `socks5`, `socks5h`:

```bash
TELEGRAM_PROXY_URL=socks5://user:password@127.0.0.1:1080
```

Слова `none`, `off`, `false`, `null`, `-` программа считает пустым значением.

#### Пароль базы

В образце пароль `dev_only_change_me`. Для локальной проверки его можно не менять: скрипт требует только непустой `POSTGRES_PASSWORD`.

Пароль записан в трёх строках и должен совпадать:

- `POSTGRES_PASSWORD=dev_only_change_me`
- `DATABASE_URL=...://alfa:dev_only_change_me@postgres:5432/alfa_course` — адрес **внутри Docker**. Хост — слово `postgres`.
- `DATABASE_URL_HOST=...://alfa:dev_only_change_me@localhost:5432/alfa_course` — адрес **с компьютера**. Хост — `localhost`.

Бот из venv берёт `DATABASE_URL_HOST`, а если она пустая — `DATABASE_URL`. Контейнер `bot` специально получает пустой `DATABASE_URL_HOST`, чтобы ходить на хост `postgres`, а не на `localhost` внутри контейнера.

Имена `alfa` и `alfa_course` оставьте как в образце. Если меняете пароль, замените его во всех трёх строках.

#### Что уже заполнено в образце

| Строка | Зачем |
|--------|--------|
| `POSTGRES_USER`, `POSTGRES_DB` | Пользователь и имя базы |
| `POSTGRES_HOST=postgres` | Имя сервиса базы в compose |
| `POSTGRES_PORT=5432` | Порт внутри Docker |
| `POSTGRES_HOST_PORT=5432` | Порт базы на компьютере. В prod по умолчанию 5433, чтобы не столкнуться с dev |
| `EMBEDDING_MODEL` | Модель векторов. Первая загрузка знаний скачивает её сама |
| `PLATFORM_BASE_URL` | Начало ссылок на материалы. Домена платформы в дампе нет, slug склеивается с этим адресом |
| `INGEST_CHUNK_SIZE=800` | Длина куска текста при нарезке |
| `RAG_TOP_K=5` | Сколько фрагментов остаётся после поиска |
| `RAG_SCORE_THRESHOLD=0.35` | Ниже этого балла ответ по фрагменту не формулируется |
| `RAG_RELATED_SCORE_THRESHOLD=0.27` | Ниже этого балла бот говорит, что в базе нет ответа. Между 0.27 и 0.35 предлагает близкий материал |
| `RAG_CLARIFY_SCORE_GAP=0.06` | Если два разных материала почти одинаково близки, бот просит выбрать |
| `LLM_TIMEOUT_SECONDS=30` | Сколько ждать один запрос к модели |
| `API_PORT=8000` | Порт `/health` |
| `DEBUG=true`, `LOG_LEVEL=DEBUG` | Подробные логи. В prod ставьте `DEBUG=false` и `LOG_LEVEL=INFO` |

Порог факта в образце не записан. В коде он `FACT_SCORE_THRESHOLD=0.45`: факт ближе этого балла уходит пользователю, иначе сообщение «Кстати…» не отправляется. Часовой пояс напоминаний — `REMINDER_TIMEZONE=Asia/Vladivostok`, опрос напоминаний — раз в `REMINDER_POLL_INTERVAL_SECONDS=15`. Длиннее `MESSAGE_MAX_LENGTH=1000` символов бот просит сократить вопрос и в поиск его не отправляет.

### Куда положить дамп

Один файл, не папка с таким же именем:

```text
src/data/backups/alfa_course_hackathon.backup
```

Проверка:

```bash
ls -lh src/data/backups/alfa_course_hackathon.backup
file src/data/backups/alfa_course_hackathon.backup
```

Ожидается файл от примерно 19 МБ, а `file` пишет `PostgreSQL custom database dump`. Пустой файл и каталог скрипт отклоняет и контейнеры не стартует.

Дамп накатывается только в **пустой** том Postgres: первый запуск или запуск после `down -purge`. Повторный `up` уже лежащую базу заново не перезаписывает. Схема `public` из дампа только читается, миграции её не меняют.

### База в Docker, бот из venv

Так удобно править код: uvicorn с `--reload` перечитывает `src/`.

#### 1. Поднять базу, миграции и знания

```bash
./scripts/dev/up-dev.sh --no-ingest
```

Флаг `--no-ingest` нужен, только если чанки уже загружены и вы не хотите гонять модель заново. На чистой базе уберите флаг:

```bash
./scripts/dev/up-dev.sh
```

Скрипт сам переходит в корень. Порядок:

1. Проверяет `.env.dev` и непустой `POSTGRES_PASSWORD`.
2. Проверяет файл дампа.
3. Поднимает Postgres и ждёт, пока в схеме `public` появятся таблицы из дампа.
4. Применяет миграции Alembic. Повторный запуск безопасен.
5. Загружает знания в `content.chunks`, если там ещё нет векторов. Первый раз долго. Если чанки уже есть, шаг пропускается.
6. Собирает и запускает контейнер `bot` и ждёт, пока `/health` ответит `ok`.

Если бот нужен только из venv, после здоровой базы контейнер `bot` можно остановить, чтобы он не занял порт 8000 и не забрал тот же токен Telegram (два процесса с одним токеном дерутся за `getUpdates`):

```bash
docker compose --env-file .env.dev -f docker-compose.dev.yml stop bot
```

Полезные варианты скрипта:

```bash
./scripts/dev/up-dev.sh --no-ingest
FORCE_INGEST=1 ./scripts/dev/up-dev.sh
INGEST_ARGS="--dry-run --limit 10" ./scripts/dev/up-dev.sh
```

`--dry-run` у загрузчика знаний не качает модель и пишет фиктивные векторы. Для настоящего бота так не оставляйте.

Остановка:

```bash
./scripts/dev/down-dev.sh          # контейнеры остановить, данные базы сохранить
./scripts/dev/down-dev.sh -purge   # ещё и тома удалить; следующий up снова накатит дамп
```

#### 2. Окружение Python

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
```

Строка с `torch` ставит сборку под процессор. Без неё pip может начать качать сборку под NVIDIA на несколько гигабайт. `requirements-dev.txt` нужен для ruff, pytest и pre-commit.

После `activate` приглашение начинается с `(.venv)`. В новом окне активацию повторяют.

#### 3. Запустить бота

```bash
uvicorn src.core.app:app --reload --host 127.0.0.1 --port 8000
```

Окно терминала остаётся занятым. Остановка: `Ctrl+C`.

В логе ожидайте баннер бота, строку про токен и «Telegram API: прямое подключение» (или строку про прокси). Затем «Прогрев модели эмбеддингов» и «Модель эмбеддингов готова». Опрос Telegram стартует параллельно прогреву: пока модель грузится, бот уже может получить `/start`. Если `getMe` не удался, опрос повторяется каждые 5 секунд, а `/health` при этом всё равно отвечает `ok`.

Потом в Telegram откройте своего бота и отправьте `/start`.

### Весь стек скриптом

Тот же `./scripts/dev/up-dev.sh` без остановки контейнера `bot`. Бот внутри контейнера — это gunicorn с одним воркером uvicorn. Код смонтирован томом `./src:/app/src`, кэш модели — том `hf_cache`. Healthcheck смотрит только на `/health` и **не** доказывает, что поллинг Telegram жив. Смотрите лог:

```bash
docker compose --env-file .env.dev -f docker-compose.dev.yml logs -f bot
```

Ищите `Run polling for bot`. Пока этой строки нет, контейнер может уже отвечать `ok` на health: прогрев модели или сеть до Telegram ещё не закончились.

Порт 8000 в этом режиме занят контейнером. Второй `uvicorn` на том же порту и с тем же токеном не запускайте.

### Как понять, что всё поднялось

Пока процесс бота жив:

```bash
curl -s http://127.0.0.1:8000/health
```

Тело ответа — текст `ok`.

В Telegram:

1. Найдите бота по имени из BotFather.
2. Отправьте `/start`. Должны прийти приветствие и три кнопки.
3. Задайте вопрос по материалам курса. Ответ модели появляется, когда заполнены `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`, а знания уже загружены.

Если бот молчит, смотрите лог того процесса, который держит токен. Частые причины: пустой или чужой `TELEGRAM_BOT_TOKEN`, два процесса с одним токеном, пустые поля LLM, Postgres не запущен (`docker compose --env-file .env.dev -f docker-compose.dev.yml ps`).

`/health` сам по себе не означает, что бот опрашивает Telegram. Пустой токен тоже оставляет health живым и пишет в лог «TELEGRAM_BOT_TOKEN пуст. Опрос Telegram не запущен.»

### Заполнение фактов

Загрузка знаний пишет чанки. Фразы «Кстати…» лежат отдельно, в `content.facts`. Пока таблица пустая, бот отвечает как обычно и факт не показывает.

Команда читает уже нарезанные материалы из `content.chunks`, просит модель вынуть одно предложение строго из текста и сохраняет фразу вместе с вектором. База и ключ LLM берутся из `.env.dev`. На каждый материал один запрос к модели. Сейчас в базе около 1800 материалов; полный прогон занимает часы и тратит токены.

Сначала проверка на двадцати материалах, из активированного `.venv`, когда Postgres уже доступен на `localhost:5432`:

```bash
.venv/bin/python -m src.modules.knowledge.facts --limit 20
```

Полный прогон — та же команда без `--limit`.

В конце лог пишет `written`, `skipped` и `failed`. `skipped` — модель ответила «нет» или текста не было, строка не создаётся. Повторный запуск заменяет факт того же материала, а не копит дубли.

Коммит один, в самом конце команды. Пока процесс не дошёл до строки «Факты записаны», другие подключения эти строки не видят. Если процесс убить раньше, вставка откатится.

На своём железе не гоняйте полный прогон без нужды.

### Prod

Для локальной проверки этот раздел не нужен. Сервис `bot` в prod-compose включён и стартует gunicorn из образа, без тома с исходниками.

1. `cp .env.prod.example .env.prod`
2. Заполнить `POSTGRES_PASSWORD` (в образце он пустой) и тот же пароль в `DATABASE_URL` и `DATABASE_URL_HOST`, плюс токен Telegram и три поля LLM. Оставить `APP_ENV=prod`.
3. Тот же файл дампа.
4. `./scripts/prod/up-prod.sh`

Postgres на компьютере слушает **5433**, HTTP бота — **8000**.

```bash
./scripts/prod/down-prod.sh
./scripts/prod/down-prod.sh -purge
```

Дополнительные переменные `up-dev.sh` и `up-prod.sh`:

| Переменная | Смысл |
|------------|--------|
| `BACKUP_REL` | путь к дампу от корня (по умолчанию `src/data/backups/alfa_course_hackathon.backup`) |
| `FORCE_INGEST=1` | нарезать знания заново, даже если чанки уже есть |
| `INGEST_ARGS` | аргументы загрузчика, например `--dry-run --limit 10` |

Ручные команды compose: [scripts/README.md](scripts/README.md).

## Что делает бот

Пользователь появляется в `app.users` при первом сообщении, по telegram id. Дальше бот ведёт диалог в `app.dialog_states` и профиль в `app.profiles`.

### Команды и кнопки

| Ввод | Что происходит |
|------|----------------|
| `/start` | Приветствие и три кнопки: задать вопрос, подобрать материалы, поставить напоминание. Текущий шаг анкеты или напоминания сбрасывается |
| `/help` | Короткая справка. Тоже сбрасывает незакрытый шаг |
| `/cancel` | «Отменил текущий шаг» и клавиатура старта |
| `/profile` | Карточка сферы, стадии и режима налога, кнопки правки |
| `/reminders` | Список напоминаний или фраза, что их нет |
| Кнопка «задать вопрос» | Просьба написать вопрос словами. Сам поиск не запускается |
| Кнопка «материалы» | Подборка по профилю |
| Кнопка «напоминание» | Сценарий «о чём напомнить» |
| Стикер, голос, фото | «Пока я понимаю только текст» |
| Текст длиннее 1000 символов | Просьба сократить. В RAG такой текст не уходит |
| Неизвестная команда | Подсказка написать вопрос или `/help` |

Пока идёт анкета или сценарий напоминания, обычный текст считается ответом на текущий шаг, а не вопросом к базе. Команды этот шаг прерывают.

### Профиль

Бот запоминает три вещи: сферу своими словами («Кофейня»), стадию (только планирую / меньше года / больше года) и режим (УСН, патент, самозанятость, другой, не знаю).

После первого содержательного ответа бот один раз спрашивает, чем человек занимается. Строка вроде «Кофейня, полгода» сохраняет и сферу, и стадию, если сфера ещё пустая. Пустая правка сферы снова открывает карточку. Режим можно назвать словами («я на УСН») вне анкеты.

Когда анкета только что закрылась, бот сразу предлагает подборку материалов. Если в профиле появился режим налога, следом может предложить напоминание о сроке этого налога.

### Подбор материалов

Подборка строится по сфере, стадии и теме последнего вопроса, не через LLM. Маршруты зашиты в коде: холодный старт для пустого профиля, учебный маршрут новичку, отдельные подборки для кофейни, маркетинга, УСН. Платный материал в подборке — одна строка пользы и ссылка, без текста урока.

Фразы вроде «что почитать» и «подбери материалы» тоже ведут в подборку, а не в поиск ответа.

### Напоминания

Свои напоминания: текст, время, повтор (один раз, каждую неделю, каждый месяц, каждый квартал). Время разбирается по фразам «завтра в 10:00», «в пятницу вечером», «через минуту». Часовой пояс — Владивосток. «Вчера» и «25:00» остаются на шаге «когда»: прошедшее время — «Это время уже прошло», кривое — «Не понял, когда напомнить».

Налоговые напоминания берутся из справочника сроков под режим профиля. У самозанятости срока в справочнике нет, бот так и говорит. К отправке добавляется оговорка, что дату лучше сверить.

Отдельная задача в том же процессе бота раз в 15 секунд ищет подошедшие напоминания и шлёт их. В логе после успешной отправки есть `reminder_sent user_id=… id=…`. Кнопки на пришедшем сообщении: готово, позже, выключить, сменить частоту.

### Ответ на вопрос

Свободный текст, который не попал в анкету, напоминание или подборку, идёт в знания.

Пока идёт поиск и формулировка, бот показывает «печатает» и одно служебное сообщение. Оно редактируется на месте и в конце становится ответом:

1. `🔎 Ищу в материалах…` — сразу.
2. `📚 Нашёл N статей, формулирую…` — только когда статьи реально найдены и началась формулировка. N — число разных материалов (по ссылке, иначе по заголовку), не обрезка «три фрагмента в промпт». Падеж: 1 статью, 2 статьи, 5 статей, 11 статей, 21 статью.
3. `Ещё пара секунд` — только если **текущая** стадия длится больше 15 секунд. Таймер сбрасывается при смене стадии: долгий поиск не затирает строку «Нашёл N» секундой позже.
4. Служебное сообщение заменяется текстом ответа. Если кусков несколько, остальные уходят новыми сообщениями.

Если рядом нашёлся факт, он уходит **отдельным** сообщением и не затирается ответом: `💡 Кстати, у меня есть интересный факт: …`. Факта нет — сообщения нет. Его не бывает на темах вне базы, на уточнениях, на «не нашёл» и на «вот близкий материал».

После нормального ответа бот спрашивает «Ответ помог?». «Да» — короткая благодарность. «Нет» — предложение переформулировать или открыть `/help`. Оценка без предыдущего ответа ничего не ломает. Если сфера ещё не известна, после ответа бот предлагает рассказать о бизнесе.

Сбой модели даёт одно сообщение про заминку, без куска ответа и без оценки. Общий сбой обработчика — «Что-то пошло не так» и `/start`.

## Как ищется ответ

Цепочка в `src/modules/knowledge/service.py`. Вектор вопроса считается один раз и идёт и в чанки, и в факты.

1. **Мимо базы, без поиска.** Виза, VIN, рецепт и капучино, курс доллара, просьба написать код, сравнение банков, попытка подменить промпт. Кофемашина — только вместе с ошибкой или «не варит». На эти вопросы модель не вызывается.
2. **Уточнение до поиска**, если вопрос слишком широкий: «кредит» без «открытие» и без «оборот»; «сколько налог» без режима в профиле; голое «как закрыть»; «касса» без сферы и режима; на УСН вопрос про расходы и налог, пока не ясен объект.
3. **Поиск.** Запрос чуть расширяется синонимами (недостача → инвентаризация, списание, магазин на патенте или УСН → розница, ассортимент → ABC). Эмбеддинг `query: …` сравнивается с чанками по косинусу. В окно попадает до 80 фрагментов с `include_in_rag`.
4. **Свёртка и лексика.** Фрагменты одной ссылки схлопываются. Среди почти равных по вектору (зазор 0.04) выше поднимается тот, где слова вопроса есть в заголовке. Учитываются опечатки: для слов от 6 букв допускается близость Левенштейна от 0.8, `ё` считается как `е`. Вопрос про НДС и УСН дополнительно поднимает материал со slug `kak-rabotat-i-ne-sojti-s-uma`, если он и так почти рядом. Этот бонус не вешается на другие статьи про лимиты.
5. **Решение.** Остаётся `RAG_TOP_K` (5).
   - балл ниже 0.27 — «в материалах такого нет»;
   - слова «виза» в вопросе обязаны встретиться в материале, иначе тоже «нет», даже при высоком балле;
   - от 0.27 до 0.35 и материал по теме — карточка близкого материала, без ответа модели;
   - два разных заголовка почти вплотную и вопрос расплывчатый — «уточните: А или Б»;
   - иначе ответ модели.
6. **Модель.** В промпт идут не больше трёх фрагментов. Платный урок туда не кладётся целиком: одна фраза пользы. Модель просят не выдумывать, не сравнивать банки и не повторять ссылку. Ссылку с UTM (`utm_source=tg_bot`, `utm_campaign=answer`, `utm_content` — slug) дописывает код, если модель сама её не вставила. Таймаут 30 секунд, затем запасная модель, если она задана.
7. **Факт.** Тот же вектор ищется в `content.facts`, берётся один ближайший. Показывается, только если балл не ниже 0.45 и ответ пошёл в модель. Текст факта уже лежит в таблице, на этом шаге модель для факта не вызывается.

Пороги 0.35 / 0.27 и окно 80 специально не ослабляются: иначе в ответ попадают чужие статьи.

### Загрузка знаний

`python -m src.modules.knowledge.ingest` читает опубликованные и не удалённые статьи, документы, глоссарий, уроки и лендинги из `public`. Текст берётся из embed-блоков (`HtmlContent`), не из пустых полей `Content`. HTML снимается, текст режется по `INGEST_CHUNK_SIZE`. Вектор считается как `passage: …`. Повторная загрузка материала заменяет его чанки.

Уроки платных курсов тоже попадают в чанки, но в ответ их тело не пересказывается. Признак платности у курсов — `Courses.TypeId`, не поле стоимости: стоимость заполнена почти нигде. Подробности таблиц дампа: [docs/data/content-schema.md](docs/data/content-schema.md).

`--limit N` ограничивает число материалов. `--dry-run` пишет векторы-заглушки и модель не качает.

## Данные

Одна база Postgres 17 с расширением pgvector. Отдельного сервера под факты нет.

| Схема | Кто пишет | Что там |
|-------|-----------|---------|
| `public` | только дамп | Каталог платформы. Имена таблиц и колонок в кавычках: `"Articles"`, `"Url"`. `"Url"` — это slug, не полный адрес |
| `app` | миграции | Пользователи, профили, состояние диалога, напоминания, справочник налоговых сроков |
| `content` | миграции и загрузчики | `chunks` — фрагменты для ответа, `facts` — короткие факты, `material_tags` — метки для подборки |

Миграции: `src/data/migrations/versions/`. Alembic в этом проекте сравнивает только схему `app`; таблицы `content` создаются явными ревизиями, не автогенерацией.

Файл `.env` в образ Docker не копируется (`.dockerignore`). Контейнер получает переменные через `env_file` compose. Поэтому «в исходниках токен есть, а контейнер его не видит» значит, что процесс запущен без `env_file`, а не что токен забыли положить в репозиторий.

## Процесс бота

HTTP-приложение — свой ASGI в `src/core/app.py`, не FastAPI. `GET /health` возвращает `ok` и не смотрит, жив ли опрос Telegram.

При старте воркера:

1. Применяются миграции. Если они падают, воркер не поднимается.
2. Если токен непустой, в фоне стартует опрос и напоминания.
3. Прогрев модели эмбеддингов идёт рядом с опросом и не блокирует `getUpdates`. Ошибка прогрева пишется в лог, опрос из-за неё не отменяется.
4. Если Telegram недоступен, опрос повторяется каждые 5 секунд. Падение этой задачи тоже пишется в лог.

Gunicorn всегда с одним воркером (`uvicorn` + lifespan `on`). Несколько воркеров не используются: каждый тянул бы свой long polling. В dev `preload_app` выключен, таймаут воркера 600 секунд, чтобы первая загрузка модели не убила процесс. В prod preload включён, таймаут 300 секунд.

Точка входа контейнера: `gunicorn -c src/core/gunicorn.conf.py src.core.app:app`. Локально для разработки достаточно `uvicorn`, как в разделе запуска.

## Тесты

Из активированного `.venv`. Интеграционные тесты ждут Postgres с накатанным дампом и миграциями, адрес берётся из `DATABASE_URL_HOST` или `DATABASE_URL_TEST`.

```bash
.venv/bin/pytest -q -m "not integration and not questions"
.venv/bin/pytest -q -m integration
.venv/bin/pytest -q tests/questions -m questions
```

Первая команда — то, что гоняет pre-commit: без базы и без живой модели. Вторая — сценарии диалогов на настоящей базе. Третья — прогон вопросов из ТЗ через живые поиск и LLM; он долгий и тратит токены, в pre-commit и в обычный CI-набор его не кладут. Лог прогона в файл:

```bash
.venv/bin/pytest -q tests/questions -m questions > questions.log 2>&1
```

Pre-commit (husky) на индексированных файлах запускает ruff и первую команду pytest. Ruff: длина строки 100, импорты, первая сторона — только пакет `src`.
